用户手册（GB/T 8567-2006）　合同/标书风险条款抽取软件 contract-extract V1.0
====================================================================================

1 引言
--------------------------------------------------------------------------------
1.1 编写目的
    本手册面向最终用户（法务、采购、企业管理者），说明 contract-extract
    V1.0 的安装、卸载、操作步骤、配置参数与常见故障处理，指导用户独立完成
    合同/标书的本地风险条款审查。结构参照 GB/T 8567-2006《计算机软件用户
    手册》大纲。

1.2 软件范围
    本软件从 PDF/DOCX 合同、协议、标书文档中抽取 15 类风险条款（期限、
    数量、价格、交付、验收、付款、违约金、责任上限、保密、知识产权、续约、
    终止、排他、数据保护、保险），逐条输出页码、原文引文与风险等级
    （LOW/MEDIUM/HIGH），并生成 JSON 结构化结果、JSON-Schema 与 Markdown
    审查清单。可选启用 LLM 增强，但默认离线即可完整使用。

1.3 术语
    - 风险级：LOW（低）/ MEDIUM（中）/ HIGH（高）。
    - 规则层：本地正则规则，无需联网。
    - LLM 增强：可选的大模型补充抽取（需 API 密钥，离线自动回退）。
    - NDJSON：每行一条 JSON 对象的流式输出文件（*.ndjson）。
    - 审查清单：依据抽取结果生成的 Markdown 待办清单（*.md）。

2 安装与卸载
--------------------------------------------------------------------------------
2.1 运行环境要求
    - 操作系统：Linux / macOS / Windows（64 位）。
    - 运行时：Python ≥ 3.11（推荐 3.11-3.13）。
    - 核心依赖：pydantic≥2、pypdf≥4、pdfplumber≥0.10、python-docx≥1.0。
    - 可选依赖（仅启用 LLM 增强时需要）：openai≥1、anthropic≥0.30。
    - 网络：默认功能完全本地运行，不要求联网；LLM 增强需可访问相应 API。

2.2 安装步骤（源码方式）
    1) 解压源码包，进入项目根目录。
    2) （推荐）创建并激活虚拟环境：
         python -m venv .venv
         .venv\Scripts\activate        # Windows
         source .venv/bin/activate     # Linux / macOS
    3) 安装依赖：
         pip install -e .             # 仅核心功能
         pip install -e ".[llm]"      # 增加 LLM 增强依赖（可选）
    4) 验证安装：
         contract-extract --version
       或在未安装环境下直接运行：
         PYTHONPATH=src python -m contract_extract --version

2.3 卸载
    - 删除虚拟环境目录 .venv 后删除源码目录即可完全卸载；如已 pip 安装，
      执行 `pip uninstall contract-extract` 移除入口。
    - 本软件不写系统注册表、不常驻进程、不产生隐藏服务，卸载干净无残留。

3 操作说明
--------------------------------------------------------------------------------
3.1 命令总览
    contract-extract [路径...] [选项]
    选项：--llm（启用 LLM 增强）| --llm-embed（同 --llm）
          --checklist（同时生成 Markdown 审查清单）
          --schema（导出 JSON-Schema）| --version（版本）
          -o FILE 或 --output FILE（结果写入 NDJSON 文件）
          --fixtures（运行内置验收套件）

3.2 单文档抽取
    将合同拖入命令行：
      contract-extract 合同.pdf
      contract-extract agreement.docx
    结果以 NDJSON 输出到屏幕，每行一个文档结果对象，包含 risk（整体风险）、
    clauses（条款列表：条款名/页码/引文/风险级/标记/明细）。

3.3 批量目录抽取（推荐工作流）
      contract-extract ./合同目录/ -o 结果.ndjson
    自动递归收集目录内所有 .pdf/.docx，逐份处理并流式写入结果.ndjson，
    全程内存占用平稳，适合 100+ 份文档的大批量审查。
    查看统计信息：处理完成后程序会打印 "processed N/M documents"；处理失败
    的文档会打印 "failed: 路径: 原因"。

3.4 生成审查清单
      contract-extract ./合同目录/ -o 结果.ndjson --checklist
    会在结果文件旁生成 结果_checklists/ 文件夹，内含每份文档的 Markdown
    审查清单（字段分组、风险级、原文页码引用、待勾选检查项）。逐项勾选后
    可作为内部复核记录。

3.5 查看输出契约与内置验收
      contract-extract --schema          # 打印输出 JSON-Schema
      contract-extract --fixtures        # 运行语料验收（召回/风险准确率）
    验收阈值：字段召回 ≥95%、风险准确率 ≥90%。

3.6 Web 演示（可选）
      contract-extract.web 或 PYTHONPATH=src python -m contract_extract.web
    浏览器打开 http://127.0.0.1:8000/，选择 .pdf/.docx 上传，即可在线查看
    条款表格、审查清单与 JSON。默认仅监听本机；对外暴露：
      HOST=0.0.0.0 PORT=8080 python -m contract_extract.web
    上传文件处理后即在临时目录删除，不留本机副本。

    注：Web 演示以"即传即查"为主，涉密文档请勿在共享/云端环境使用。

4 配置与参数
--------------------------------------------------------------------------------
4.1 环境变量
    LLM_OFFLINE=1       强制离线模式：即使配置了 API 密钥也不发起 LLM 调用，
                        结果完全由规则层产出（默认 0/关闭）。
    OPENAI_API_KEY=…     启用 OpenAI LLM 增强（配合 --llm）。
    OPENAI_MODEL=…       OpenAI 模型名，默认 gpt-4o-mini。
    ANTHROPIC_API_KEY=…  启用 Anthropic LLM 增强（配合 --llm）。
    ANTHROPIC_MODEL=…    Anthropic 模型名，默认 claude-3-haiku。
    HOST / PORT          Web 演示监听地址与端口（默认 127.0.0.1 / 8000）。
    PYTHONPATH=src       以源码方式运行时需将 src 加入模块搜索路径。

4.2 LLM 增强说明（成本控制）
    - LLM 默认关闭；仅当显式加 --llm 且配置相应 API 密钥时才发起云调用。
    - 每次调用仅发送文档前 3 页、每页 900 字符，请求 max_tokens=1500，
      按当前主流小模型计费，单份估算 <US$0.01。
    - LLM 只补加规则未发现的条款域，绝不删除规则结果；调用失败自动回退
      规则结果，业务不中断。
    - 敏感文档建议保持 LLM_OFFLINE=1 或直接不加 --llm，全程零上云。

4.3 结果文件约定
    - *.ndjson：UTF-8，每行一个 JSON 对象（可按行流式解析）。
    - *_checklists/*.md：审查清单，Markdown 文本。
    - 输出 Schema 见 --schema 或 schema/documented_result.schema.json。

5 故障处理与 FAQ
--------------------------------------------------------------------------------
5.1 故障处理
    现象 1：命令找不到 contract-extract。
      处理：确认已激活虚拟环境并执行 `pip install -e .`；或用
       PYTHONPATH=src python -m contract_extract。

    现象 2：处理 .pdf 报 "UnsupportedFormatError / pypdf could not read"。
      处理：多为损坏、加密或扫描件。先解密/解除权限（如用阅读器另存为
      新 PDF）；扫描件需先 OCR 成文本型 PDF 再处理。

    现象 3：批量处理中部分文档失败、其余正常。
      处理：属预期容错——失败文档会以 "failed:" 列出原因，成功文档结果
      照常写入；对失败文档单独重跑或人工检查。

    现象 4：--checklist 未生成 .md 文件。
      处理：--checklist 必须配合 -o FILE 使用；将结果输出到文件后再
      生成同名 *_checklists 目录。

    现象 5：启用 --llm 但控制台提示 "Falling back to the rule layer"。
      处理：说明当前为离线态（未配置密钥或 LLM_OFFLINE=1），规则层结果
      仍然完整，属正常回退，无需处理。

    现象 6：Web 演示上传提示 "Unsupported format" 或 "File too large"。
      处理：仅支持 .pdf/.docx 且 ≤20MiB；请压缩或拆分大文件后重试。

5.2 常见问题 FAQ
    Q1：软件会联网上传我的合同吗？
      A1：默认不会。规则层完全本地运行；仅当您显式输入 --llm 且配置密钥，
          才会向前 3 页（900 字符/页）文本摘要发起 LLM 调用。设置
          LLM_OFFLINE=1 可彻底禁用。

    Q2：识别结果的准确度如何？
      A2：内置 20 份混合语料验收：字段召回 100%、风险准确 100%（阈值
          95%/90%）。规则可复现、附带原文页码，便于人工复核；复杂条款请以
          人工核对为准。

    Q3：支持哪些文件格式？能处理扫描件吗？
      A3：支持 .pdf 与 .docx（.doc 尝试按 docx 处理）。扫描件为图像型 PDF，
          需先 OCR 转文本型后再处理。

    Q4：结果里的页码准确吗？
      A4：PDF 页码来自真实页数据；DOCX 无原生页码，页面为按行数估算值，
          以此定位原文段落，最终请以原文为准。

    Q5：如何把结果交给下游系统？
      A5：NDJSON 每行即一个 JSON 对象，可用任意 JSON 解析器读取；字段契约
          以 JSON-Schema（--schema）为权威定义，可直接用作数据校验。

    Q6：本软件能替代律师审阅吗？
      A6：不能。本软件为辅助性审查工具，辅助发现风险条款与定位原文，不
          提供法律意见；重大决策请咨询执业律师。

    Q7：可以商用/二次开发吗？
      A7：软件按本文档配套协议使用；二次开发请在遵循许可的前提下进行并
          重点核验自定义规则的正则与阈值。

    Q8：卸载后会有残留吗？
      A8：无。删除代码目录与虚拟环境即可；程序不写注册表、不创建服务、
          不在系统目录驻留文件。
